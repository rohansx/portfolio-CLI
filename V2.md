## 1. Thesis & goals

### The one-line thesis the site must communicate

> **"Rohan builds infrastructure for the agent era — and he ships constantly."**

Every design and feature decision serves that sentence. Rohan's 2026 project fleet (agidb, ctxgraph,
veyo, clipxd, cloakpipe, workz, glyph, spnr, illuminate, primd, leadecho, convox, moltnet) is an
agent-infrastructure ecosystem. V1 shows almost none of it. V2's job is to **prove the thesis, not
list projects**:

- The portfolio itself becomes **agent-legible** (`curl rohan.sh`, `/llms.txt`, an MCP endpoint) —
  the site *is* Exhibit A of what he builds.
- The terminal mode becomes a **real information architecture** (a navigable filesystem), not a menu
  of novelty commands.
- A live **ship log** (GitHub telemetry) makes his velocity visible in the first 10 seconds.

### Goals

1. One source of truth for all identity/project data; zero content drift between modes.
2. One coherent design system across terminal, GUI, blog, and resume.
3. First-visit "whoa" moment on both desktop (terminal) and mobile (GUI).
4. Shareable blog posts with correct social embeds (SSG meta tags).
5. No secrets in the client bundle. No fabricated metrics. No flaky third-party APIs in the critical path.

### Non-goals

- No CMS, no database for content (data lives in the repo as typed TS/JSON).
- No account system, no comments.
- Don't rebuild the blog posts' content — only their rendering/authoring pipeline.
- Don't chase feature parity with V1's novelty commands (most are deleted — §10).

## 3. Architecture: one data source, three renderers

```
                       ┌──────────────────────────────┐
                       │   src/data/profile.ts        │   ← single source of truth
                       │   (typed, exports Profile)   │
                       └──────────────┬───────────────┘
          ┌───────────────┬───────────┼───────────────┬──────────────────┐
          ▼               ▼           ▼               ▼                  ▼
     GUI renderer    Terminal     Build-time      /api/mcp          npx card
     (React DOM)     renderer     generators:     (MCP server,      (separate
                     (React,      /llms.txt       Vercel fn)        npx-rohan
                     virtual FS)  /resume.json                      repo, later)
                                  /resume.txt (ANSI)
                                  resume page + PDF link
                                  blog meta HTML shells
```

**Rule: no component may hardcode identity/project/experience content.** Everything renders from
`profile.ts`. The blog is the only other content source (markdown files, §5.6).

### 3.1 `Profile` schema (create as `src/data/profile.ts`)

```ts
export type ProjectStatus = 'active' | 'stable' | 'experimental' | 'archived';
export type Shelf = 'agent-infra' | 'security-privacy' | 'devtools-products';

export interface Project {
  slug: string;              // filesystem name in terminal, e.g. "cloakpipe"
  name: string;              // display name, e.g. "CloakPipe"
  oneLiner: string;          // ≤ 120 chars, no trailing period
  description: string;       // 2–3 sentences for cat README / GUI expanded view
  shelf: Shelf;
  status: ProjectStatus;
  lang: string;              // primary language, e.g. "Rust"
  langColor: string;         // GitHub language color hex
  repo?: string;             // github URL if public
  site?: string;             // product URL if any
  demo?: string;             // asciinema cast id / local .cast path (Phase 4)
  blogSlugs?: string[];      // related posts, cross-linked both ways
  featured: boolean;         // featured projects appear on GUI homepage + `ls ~/projects` top block
}

export interface Experience { company: string; url: string; role: string;
  period: string; location: string; highlights: string[]; }

export interface Endorsement { quote: string; author: string; authorUrl: string;
  role: string; sourceUrl: string; /* link to the real PR for verification */ }

export interface Profile {
  name: string; handle: string; title: string; bio: string; thesis: string;
  location: string; email: string; website: string;
  socials: { github: string; twitter: string; linkedin: string; peerlist?: string };
  resumeUrl: string;                    // dub.sh/rohan-cv
  experience: Experience[];
  projects: Project[];
  endorsements: Endorsement[];
  skills: Record<string, string[]>;
  achievements: { title: string; event: string; teams: string }[];
}
```

Canonical content for this file is in **§9**. `data/resume.ts` and the project/link arrays in
`config.tsx` are deleted after migration (§10).

## 5. Phase 1 — Foundation

### 5.1 Stack migration: CRA → Vite

- Vite 6 + `@vitejs/plugin-react`, React 18 (or 19 if trivial), TypeScript 5.x strict.
- Remove: `react-app-rewired`, `react-scripts`, `config-overrides.js`, all webpack polyfill deps
  (`assert`, `browserify-zlib`, `https-browserify`, `path-browserify`, `stream-*`, `url`, `util`),
  `axios` (use `fetch`), `react-helmet` (see §5.6 for meta handling), `web-vitals` unless re-wired.
- **One lockfile.** Pick one package manager (bun is fine — `bun.lock` exists), delete
  `package-lock.json` + `yarn.lock`, remove `packageManager: yarn@3.2.0` from package.json.
- Routing: keep it minimal — `react-router-dom` with routes `/`, `/blogs`, `/blogs/:year/:slug`,
  `/resume`. Replace the current `window.history.pushState` hand-rolling and the
  `switch-to-gui` CustomEvent hack with router state / context.
- Kill the `fakeApp` shim: commands get a proper typed context
  `CommandContext { profile, posts, navigate, clear, setTheme, print }` (§6.3).
- Scripts: `dev`, `build`, `preview`, `lint`, `test`, `generate` (build-time generators, §7).

**Acceptance:** `bun run build` produces a working site; bundle has zero webpack polyfills;
`grep -r "fakeApp\|CustomEvent('switch-to-gui'\|react-app-rewired" src/` → empty.

### 5.2 Design system — tokens

hardcoded hex values from component SCSS (the GUI module is the worst offender).

### 5.3 Themes (replace the V1 five)

Exactly **three** themes, all defined as token overrides on `:root[data-theme=…]`, applying to
**every mode** (terminal, GUI, blog, resume):

1. `graphite` (default) — the palette above.
2. `paper` — real light mode: `--bg:#faf9f7`, `--fg:#1a1a1a`, `--accent:#1d7a4f`, etc.
   Must pass WCAG AA (4.5:1) for `--fg` and `--fg-muted` on `--bg`.
3. `crt` — the fun one: green-phosphor palette + scanline overlay + subtle flicker. Keep the existing
   scanline/CRT CSS from `themes.scss` but only for this theme.

`matrix` survives **only** as an easter-egg command (digital-rain animation, §6.5), not a theme.
Delete `retro`, `cyberpunk`, `hacker` themes. Theme persists in localStorage; respects
`prefers-color-scheme` on first visit (dark→graphite, light→paper).

### 5.4 Iconography

- **Delete Font Awesome entirely.** Replace with unicode/box-drawing glyphs: `▸ ▪ ● ⬡ ○ ↗ $ ~ │ ─`.
- Status dots: `●` colored by `--status-*`. External links: `↗`. Section markers in GUI: `§` or `//`.
- No emoji anywhere in UI chrome (D14). Emoji allowed inside blog prose only.

### 5.5 Layout & mode logic

- **Default mode:** desktop (pointer:fine, ≥768px) → **terminal**; mobile → **GUI**. Returning
  visitors get their last mode (localStorage `mode`). URL `?mode=gui|term` overrides both.
- Terminal window: keep draggable/resizable + traffic lights on desktop. On mobile the terminal
  (if user switches to it) is **full-bleed**, fixed input at bottom, and shows a horizontal row of
  **tappable command chips** (`ls ~/projects` · `whoami` · `blog` · `gui`) above the keyboard.
- Nav (both modes, one component): `[1 terminal] [2 blog] [3 resume]` style on terminal,
  `terminal / blog / resume` minimal text on GUI — same component, two skins, working hotkeys.
- Status bar (terminal): left `● online` + mode toggle (text, no emoji); center: theme name;
  right: **ship-log summary** once Phase 4 lands (`▲ 14 commits this wk`), local time. No visitor count.
- Remove tsparticles (D15). Atmosphere comes from the CRT theme and a very subtle radial gradient
  behind the terminal window.
- GUI mode: keep the 640–680px single column, but in mono with `$`-flavored details
  (section headers like `rohan@sh:~$ cat experience.md` rendered as faint decorative text).
- Endorsements (D16): render as **styled quote cards** from `profile.endorsements` — quote text,
  author, role, `↗ view on GitHub` linking to the real PR. Delete the PNG screenshots.

### 5.6 Blog pipeline

- **SEO/social embeds (D12):** add a build step (`scripts/generate-meta.ts`, run in `build`) that

- Homepage (GUI): "Recent writing" section — latest 3 posts.

  with `blogSlugs` show "read the build log ↗".

### 6.3 Command engine

- Replace the `Map<string, Command>` + `fakeApp` with a proper parser: tokenize → resolve alias →
  match command → parse args/flags. Commands are pure functions
  `(args: string[], ctx: CommandContext) => ReactNode | Promise<ReactNode>`.
- Keep `|` grep support (`ls ~/projects | grep rust`) — but implement it on the command's **text
  representation** (each command returns `{ node, text }`) instead of the fragile
  `extractTextFromJSX` walker. `&&` chaining stays.
- **Tab completion v2**: completes commands *and* paths (context-aware: `cd <Tab>` cycles dirs,
  `cat <Tab>` cycles files). Keep ghost-text inline suggestion; Tab accepts, `→` accepts,
  Shift+Tab cycles alternatives.
- Unknown command: keep shake animation + suggest nearest command (levenshtein ≤ 2:
  `command not found: porjects — did you mean projects?`).
- History (↑/↓) and Ctrl+K palette carry over. Palette items grouped: Navigate / Read / Fun.

### 6.4 First-visit experience (terminal)

On first load (no localStorage flag), **auto-type** (~35 chars/s, skippable by any keypress):

```
rohan@sh:~$ whoami
  → identity card renders
rohan@sh:~$ ls ~/projects
  → rich project listing renders
rohan@sh:~$ █
```

Then the hint line: `type help, or press 1 for the point-and-click version`.
This guarantees the "whoa" moment without requiring the visitor to know what to type. Returning
visitors get a plain prompt + one-line hint.

### 6.5 Easter eggs policy

Exactly three (`sudo`, `matrix`, `curl rohan.sh`), none advertised in `help`. Whimsy is discovered,
not menu'd.

**Phase 2 acceptance:** every command in §6.2 works incl. tab-completion of paths; `cd
projects/security-privacy && ls && cat cloakpipe/README.md` works as a chain; first-visit autotype
runs and is skippable; no command references `config.tsx` data; mobile terminal is full-bleed with

## 7. Phase 3 — Agent-legibility layer (the signature feature)

**Concept: "three frontends, one person."** The portfolio is DOM for humans-with-mice, TTY for
humans-with-keyboards, and structured data + MCP for agents. Nobody else has this; it's also
literally the thesis of Rohan's tools. Market it with one line in the GUI footer and README:

> *This site renders three ways: DOM, ANSI (`curl rohan.sh`), and MCP (`rohan.sh/mcp`). Agents are visitors too.*

### 7.1 Build-time generators (`scripts/generate.ts`, runs in `build`)

From `profile.ts` + blog index, emit into `dist/`:

1. **`/llms.txt`** — the llms.txt convention: H1 name, blockquote summary, sections with links to

## 11. Security requirements

1. **No secrets in the client bundle — ever.** Only `VITE_`-prefixed vars may reach the client, and
   none of them may be tokens. The Upstash write token currently shipped in V1 bundles **must be
   rotated** (Phase 0.9) regardless of what else happens.
2. Counters (if kept): `/api/visit` Vercel function — server-side Upstash token, sessionStorage
   guard client-side, IP-based rate limit (10/min), `INCR` only — the function whitelists exact
   Redis commands.
3. `/api/activity`: `GITHUB_TOKEN` server-side only, minimum scopes (public read), response cached
   (`s-maxage=900, stale-while-revalidate=3600`).
4. MCP endpoint: read-only tools only; no tool may echo arbitrary user input into responses; rate
   limited (§7.3).
5. Markdown rendering: sanitize (DOMPurify or equivalent) — blog markdown is trusted today but the
   pipeline shouldn't assume it forever.
6. No `eval` anywhere. CSP header via `vercel.json`: `default-src 'self'`; allow
   `img-src 'self' avatars.githubusercontent.com data:`; `connect-src 'self' api.github.com`;
   adjust for asciinema player chunk if self-hosted (it is — so no extra origins).
7. `talk` (if built): strict rate limits, system-prompt guardrails, visible bot disclaimer.
